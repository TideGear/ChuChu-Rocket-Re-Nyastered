- Dreamcast image setup / dump checks: GDI and separate-file CUE extraction are **partial**. GDI descriptors define LBAs/types/sizes/filenames/offsets; CUE descriptors define their referenced raw files, track modes and indices. Both paths reject missing/malformed tracks, unsafe paths and invalid data layouts before extracting the high-density ISO. CUE supports raw BINARY separate files, AUDIO/MODE1 sectors, INDEX 00/01, pregaps represented in the indexed raw file, and multiple tracks sharing a raw file; unsupported external PREGAP/POSTGAP or malformed layouts fail explicitly. Direct descriptor selection is preserved even if a sibling descriptor exists; selecting a folder with multiple GDI/CUE files is reported ambiguous. Arbitrarily named track files referenced by the original USA CUE extract all 1,305 files SHA-identically to the matching tested GDI extraction; all 15 audio WAVs are byte-identical. Synthetic tests cover split data tracks, CUE mode/LBA handling, shared-file tracks, path safety and discovery. Clean Windows setup accepts directly selected `.gdi`/`.cue` or folders; raw tracks remain beside the descriptor or under safe relative paths. Optional BIOS discovery from a directly selected descriptor searches that folder and immediate children (9-test regression suite plus fresh-cache CUE+user-BIOS full setup/build; both BIOS font atlases exported). Fresh direct CUE-only setup with no BIOS/mobile files builds with the pinned Zig toolchain and yields 128 models, 15 CD WAVs, 128 cue WAVs, Dreamcast graphics and Puzzle/Battle/Stage Challenge. Both checkout and packaged `ccr --prepare` pass on a directly selected CUE. Six CUE-only title/menu/Puzzle/Challenge/Battle/selector captures were visually checked. On 2026-11-22, two new `setup.cmd` runs used separate empty caches: directly selected USA CUE only, and tested USA GDI plus iOS 1.1.2 IPA. Both built with the pinned Zig toolchain, reported Puzzle/Battle/Stage Challenge and zero input errors; CUE-only selected Dreamcast graphics, combined selected mobile graphics, and both retained `dreamcast/models.bin` and all 15 CD WAVs. Each fresh cache rendered visually inspected 640x480 headless DC_TITLE, Puzzle, Challenge and Battle routes. These setup/build/route results are not Flycast parity. Fresh GDI+iOS 1.1.2 setup retains Dreamcast models/audio while selecting mobile graphics. Manifests hash GDI/CUE descriptors and referenced tracks (or all supported loose raw inputs). CHD v5 GD-ROM input is **partial** (2026-11-24): `tools/chd_reader.py` decodes the CHD directly (not via `chdman extractcd`, whose cue mislays the high-density area): v5 header, Huffman/RLE compressed map with map CRC, uncompressed maps, cdlz/cdzl/cdfl hunks, self-referencing hunks, ECC/sync regeneration, `CHGD` track table with PAD/PREGAP/PGTYPE/POSTGAP. It requires every hunk CRC-16, the header raw-data SHA-1, a Mode 1 sector at each data track start, consistent sector-header addresses and track 03 at LBA 45000 before extraction; data tracks are written cooked from INDEX 01 and audio tracks little-endian including stored pregaps (as a raw GDI). cdzs (zstd), parent CHDs, v3/v4 files, the pre-2013 `CHGT` layout and CD-ROM (`CHT2`) CHDs are reported. Evidence: `tools/test_chd_reader.py` (11 tests): FLAC frames from ffmpeg's independent encoder (4 stereo modes, fixed/LPC up to order 32, partition orders 0-8, escape/exact Rice) decode bit-exactly; regenerated P/Q parity satisfies the ECMA-130 syndrome equations; a synthetic six-track GD-ROM CHD (mixed codecs, RLE map, self hunks, non-stored data-track pregap, last data track holding a file) extracts all files and audio exactly; damaged hunks and unsupported variants fail. Open: the synthetic writer follows the reader's own reading of the format (checked against libchdr's source, not against chdman output), so the real USA CHD must still pass setup (its SHA-1 gate) with SHA-identical 1,305 files and 15 WAVs versus the GDI/CUE. Other CUE layouts, regions and dump certification against independently known-good hashes remain open.
