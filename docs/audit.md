- Dreamcast image setup / dump checks: GDI and separate-file CUE extraction are **partial**. GDI descriptors define LBAs/types/sizes/filenames/offsets; CUE descriptors define their referenced raw files, track modes and indices. Both paths reject missing/malformed tracks, unsafe paths and invalid data layouts before extracting the high-density ISO. CUE supports raw BINARY separate files, AUDIO/MODE1 sectors, INDEX 00/01, pregaps represented in the indexed raw file, and multiple tracks sharing a raw file; unsupported external PREGAP/POSTGAP or malformed layouts fail explicitly. Direct descriptor selection is preserved even if a sibling descriptor exists; selecting a folder with multiple GDI/CUE files is reported ambiguous. CHD v5 GD-ROM input is **partial** (2026-11-24): `tools/chd_reader.py` decodes the CHD directly (not via `chdman extractcd`, whose cue mislays the high-density area): v5 header, Huffman/RLE compressed map with map CRC, uncompressed maps, cdlz/cdzl/cdfl hunks, self-referencing hunks, ECC/sync regeneration, `CHGD` track table with PAD/PREGAP/PGTYPE/POSTGAP. It requires every hunk CRC-16, the header raw-data SHA-1, a Mode 1 sector at each data track start, consistent sector-header addresses and track 03 at LBA 45000 before extraction; data tracks are written cooked from INDEX 01 and audio tracks little-endian including stored pregaps (as a raw GDI). cdzs (zstd), parent CHDs, v3/v4 files, the pre-2013 `CHGT` layout and CD-ROM (`CHT2`) CHDs are reported. Evidence: `tools/test_chd_reader.py` (11 tests): FLAC frames from ffmpeg's independent encoder (4 stereo modes, fixed/LPC up to order 32, partition orders 0-8, escape/exact Rice) decode bit-exactly; regenerated P/Q parity satisfies the ECMA-130 syndrome equations; a synthetic six-track GD-ROM CHD (mixed codecs, RLE map, self hunks, non-stored data-track pregap, last data track holding a file) extracts all files and audio exactly; damaged hunks and unsupported variants fail. Open: the synthetic writer follows the reader's own reading of the format (checked against libchdr's source, not against chdman output), so the real USA CHD must still pass setup (its SHA-1 gate) with SHA-identical 1,305 files and 15 WAVs versus the GDI/CUE. Other CUE layouts, regions and dump certification against independently known-good hashes remain open.
