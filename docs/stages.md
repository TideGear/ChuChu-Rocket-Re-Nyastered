# Stage registry (first pass)

Generated by `tools/stage_registry.py` into `docs/stage_registry.json` (board key = SHA-1 of tiles + walls,
arrow counts kept as an attribute). Not yet included: Dreamcast built-in stages, GBA stages, the larger
Android `ccr0.png` pack family, user-made/downloaded stage formats.

## Formats
- **Mobile struct (380 bytes)**: tile grid 12x9 at 0x00; wall layers at 0x6c (rows of 25: 12 horizontal edges
  then 13 vertical edges); arrow counts at 0x15c..0x15f; title (21 bytes) at 0x160; checksum at 0x178.
- **Dreamcast/DLC slot (1536 bytes)**: a 25x19 lattice (walls at even/odd positions, cells at odd/odd) in the same
  geometry. A VMS puzzle pack holds 25 puzzles (24 full slots plus a shortened 25th). The Android function
  `FUN_0002e6cc` converts this text-style map into the mobile struct, so the two are the same format family.
- **Cell code mapping (learned from wall-identical pairs, no unknown codes remained)**:
  `0x09`->0 floor, `0x0a`->1 rocket, `0x07`->0x11 hole, `0x3d..0x40`->9..0xc mouse (4 directions), `0x47..0x4a`->0xd..0x10 cat (4 directions).
  Mobile tile codes: 0 floor, 1 rocket, 9..0xc mouse, 0xd..0x10 cat, 0x11 hole (consistent with Android `Editor::convertField`:
  type 1 cat, 2 mouse, 3 rocket, 4 hole).

## Dreamcast built-in stages (located)
All in `ENGLISH|FRENCH|GERMAN|SPANISH|JAPANIESE/` on the disc (identical boards in every language; titles localized):
- `PZSTAGE100.DAT`: 100 puzzles, 1536-byte binary lattice slots (header 640 bytes). Boards identical to the mobile main-100 set, same order.
  Japanese file carries Japanese titles; the other four languages carry English titles.
- `BTSTAGE25.DAT` (battle) and `CHSTAGE25.DAT` (challenge): 25 stages each, 477-byte ASCII text maps (25 chars x 19 rows + CRLF).
  Byte-identical to the two 11,925-byte resources present in every mobile build (iOS 1.0.2, HD 1.0, 1.1, 1.1.2, Android 1.15).
- `KEY_STAGE000.BIN`, `SG_DPLDR.BIN`, `BALOON*.DAT`: not stages (purpose unidentified).
- ASCII text-map rule (from Android `FUN_0002e6cc`): `'7'`->0x11, `'9'`->0, other chars -> char-0x40; wall where the char is `'1'`.

Mobile therefore = Dreamcast built-ins (100 puzzle + 25 challenge + 25 battle) plus 424 extra puzzle stages
(24 tutorial + 16 groups of 25 not present in the Dreamcast disc files).

Updated union: 595 unique boards (503 puzzle + 50 battle/challenge + 42 DLC-only). Still to add: GBA stages (the GBA is said to
include 2,500 of the Dreamcast community puzzles), the 424 extra mobile stages' provenance, and any user-made stage formats.

## GBA stages (located, `tools/gba_stages.py`)
ROM `ChuChu Rocket! (USA) (En,Ja,Fr,De,Es).gba`. Cells are little-endian halfwords, 9 rows x 12 columns: high nibble = walls
(bit12 right, bit13 bottom, bit14 left, bit15 top), low 12 bits = content.
- **Main set**: 100 records at 0xAF3E8, stride 296 (216 bytes cells + 80 bytes extras; title at +256 as UTF-16LE with char-0x20). Titles
  match the mobile/Dreamcast list in order ("Where to go?" ... "Panic!!"). 98 of 100 boards identical to the Dreamcast/mobile puzzle set,
  2 differ (variants to review).
- **User-puzzle set**: 2,466 valid records (2,462 unique boards) between 0xB6C90 and ~0x151F90, stride 256 (216 cells + 40 extras, no title).
  Wikipedia says the GBA carries 2,500 of the 17,000 user puzzles uploaded to the Dreamcast servers; this matches (2,466 valid slots of ~2,483).
- Content codes: `0x000` floor, `0x020` rocket, `0x080` hole, `0x100..0x103` mouse (direction), `0x200..0x203` cat (direction)
  (mapped from 99 matched pairs and the mobile editor code).
- **Overlay bits `0x40/0x44/0x48/0x4C` = the stage's reference solution arrows** (position + direction). Evidence: in 99 of the 100 main stages the number
  of overlay cells per direction equals the mobile arrow-count fields exactly (overlay direction d -> mobile count index (d+3)%4), and the positions
  cluster on board edges: `0x40` on the left column, `0x44` on the top row, `0x48` on the right column, `0x4C` on the bottom row (arrows placed at the
  edge pointing inward). They can overlay any content (`0x14C` = a mouse start under a solution arrow). The mobile struct keeps only the counts, so
  the GBA is the source for solution positions (usable for hints and for solution-replay tests). Ignored for the board key.
