# Dreamcast DLC files (notes, 2026-11-13)

Files in the user's `Dreamcast\DLC` folder: `Cartoony`, `UFOCow`, `DEChar` (character packs) and `PuzzleP`, `DEPuzzle` (puzzle packs), each as a `.VMI` (108 bytes, Dreamcast file-info: checksum, description, copyright "Dreamcast..." and file name) plus a `.VMS` (VMU save image).

## .VMS layout (all five)
- 0x00: 16-byte ASCII description `CHU_CHU__C00` (characters) / `CHU_CHU__D01` (puzzles); 0x10: 32-byte Shift-JIS long description (Japanese titles; `UFOCow` has the English `CHUCHU!/CHARA`); 0x30: 16-byte application id; icon frame count / animation speed follow, the 32-byte 16-colour icon palette is at 0x60 and the 32x32 4-bit icon (512 bytes) starts at 0x80.
- Character packs: 17,408 bytes. The icon is 32x32 (0x80..0x27F); from 0x280 the payload is **8 ordinary Dreamcast texture files (GBIX + PVRT, ARGB4444 twiddled, 32x32, 2,080 bytes each = 16,640 bytes)**. They are the four facing directions of the mouse-side character and of the cat-side character: `Cartoony` = cartoon mouse and cat, `UFOCow` = cow (mouse) and UFO (cat), `DEChar` (Dreamcast Express) = the Dreamcast Express mascots (Candy and Dandy, per the Time Extension report below; the first guess of a train-style pair was wrong). `tools/vms_skin.py <pack.VMS> <out dir>` extracts and decodes them (verified visually on all three packs). The images are whole drawn characters (full cat/cow/UFO silhouettes in four poses), i.e. **2D sprite-style art, not retextures of the 3D models**: the game's own `c_cat01-04` / `c_mouse01-10` textures are abstract parts (colour fields, eye blob, spiral) made to wrap 3D meshes. So a skin most likely makes the game draw flat 2D characters instead of the 3D ones (correcting an earlier inference). How the game selects and draws them (poses vs direction/animation, which cat/mouse role each half is) still has to be read from the code. The ids `0x6f22..0x6f68` (Cartoony/DEChar) and `0x73d2..0x73d9` (UFOCow) are the packs' own texture ids; they do not match any texture in the disc files.
- Puzzle packs: 38,400 bytes = 512-byte header + 25 puzzle slots (24 full 1,536-byte slots plus a shortened 25th) as in [stages.md](stages.md); `DEPuzzle` and `PuzzleP` are readable and their boards are in the stage registry.

## How the skin format was found
Plain and twiddled interpretations of the whole payload gave noise because the payload is a sequence of texture *files*; the bytes at 0x280 read `GBIX` and 0x290 `PVRT` with header fields pixel format 2 (ARGB4444), data format 1 (twiddled), 32x32. The VMU file code in `1ST_READ.BIN` handles the name prefixes `CHU_CHU__RCT/E/D/C00/D00/NET` (strings at 0x8C0B4CF5..0x8C0B4D31; users: 0x8C020A40..0x8C0219B4) through a generic read helper at 0x8C0F1968.

## The October 2024 find (identified)
Time Extension, Oct 2024 ("A missing piece of ChuChu Rocket DLC was just discovered by accident", https://www.timeextension.com/news/2024/10/a-missing-piece-of-chuchu-rocket-dlc-was-just-discovered-by-accident): user @eisnerguy1 found a pack on a **Dreamcast Express Vol. 6 demo disc**; it "includes 25 new puzzles and a new set of characters (the DC Express mascots)", archived on the Dreamcast Live site. In the user's DLC folder that matches the two Dreamcast Express files: **`DEPuzzle`** (25 puzzles, VMI comment "CCR Puzzles") and **`DEChar`** (character set, VMI comment "CCR Char"), both with the `DE` prefix and the "Dreamcast Express" file-info strings. The other three (`Cartoony`, `UFOCow` = character packs; `PuzzleP` = Sonic Team's puzzle expansion) are the earlier archived packs. This identification rests on the news report plus file names; the pack contents themselves (25 puzzles, mascot art) are verified from the files.

## Arrow counts of the DLC puzzles: not found in the obvious fields (2026-11-13)
After the 475-byte lattice of a 1,536-byte puzzle slot comes a small header (a type byte, a few bytes, then the title: 21 bytes of Shift-JIS or ASCII, e.g. "CROSSROAD", at +16) and then a blob that looks packed. The stage registry holds 8 DEPuzzle boards that are duplicates of mobile stages whose arrow counts are known (mobile struct bytes 0x15C..0x15F); testing the header bytes at +1..+2 (as four nibbles) and +12..+15 (as four bytes) against those 8 matched only the two one-arrow stages, so the counts are not stored in either place in a simple form (they may be inside the packed blob, or derived by the game from a stored solution). Consequence: the DLC puzzle sets cannot yet be played with the correct arrow stock; the 8 duplicated DEPuzzle boards could take the mobile counts, the other 42 boards need the format decoded (or a solver run to find the minimum arrow set).
